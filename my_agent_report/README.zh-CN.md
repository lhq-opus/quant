# 阅读说明：从 Agent 推广到端到端交付

我为当前公司的管理层准备了[《从 Agent 推广到端到端交付：米哈游的决策与反思》](report.zh-CN.md)，以我在米哈游的 agent 开发工作和观察为基础，以更早的字节跳动经历作为比较背景。

[英文阅读说明](README.md) · [英文报告](report.md)

报告是第一人称工作草稿。米哈游核心回顾覆盖 2025 年 11 月至 2026 年 7 月，另补充约 2026 年 8—9 月 Anuttacon 的动向。报告通过 Project S、MCP 重构、个人记忆和 OpenCode 验证解释 harness 工程，并分析为什么有用的单点结果尚不能证明完整数据流程能够可靠交付。各阶段存在重叠，早期的流程目标与后续的基建工作分别记录。

七个按时间排列的案例，均围绕**决策与行动、可能原因、关键结果**展开：

1. 2025 年 11—12 月：有限的起点与共享平台讨论，并补充早期运行时研发招募的背景。
2. 2026 年 1 月 OpenClaw 热潮之后：Echo 的广泛采用。
3. Echo 之后：二—四月的个人研效重点、框架与 skill 扩张、服务端项目叫停，以及成本事件复盘。
4. 3—4 月：MCP、权限、推进落差与部门 OpenClaw 停用。
5. 4 月开始推动：Project S 的 harness 与数据飞轮、架构和推广缺口，以及我以 FDE 职责适配数据开发的经历。实际改动包括记忆补救、由 subagent stop hook 运行数据质量脚本，以及流程和模型调整；业务方定义和调整验收标准，我提供基建、保障模型尽可能遵循，数据回流周期也限制迭代。约两个月参与工作的具体起止时间仍待确认。
6. 5—7 月：harness 与基建重构，伴随再次开展 agent 项目及 ToB/FDE 需求；OpenCode 二开的交付与验证框架，以及我推进的个人记忆系统。项目重新开展和人员变化的具体日期仍待确认。
7. 约 8—9 月：Anuttacon 在向投资人所投企业推广自研模型时，认识到需要 FDE 支持。内部原则草案与米哈游案例对照；此前公开产品、模型研究和 AnuNeko 停服提供背景，不将其描述为转型做 FDE 服务。

报告区分我的经历与判断、内部初步结论、公开证据，以及待我审阅的暂定分析；将记忆检索链路与用于训练模型的反馈分开。决策选项注明对应案例，以及评价它需要的结果。尚未独立核实的近期招聘和客户活动，仍归因于我的了解。

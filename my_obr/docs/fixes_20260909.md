# my_obr 修复说明：保留实验策略与函数结构

本文记录安全修复提交 `c3b5779` 的历史行为。后续已按用户要求扩展为 30 列，新增按源 F
累计的输出统计，买四列采用 `bo4`；下文“21 列”“F 只更新订单登记”等描述仅适用于
该历史提交。当前输出规则见 [30 列 book 说明](book_30_columns.md)。

本轮修复由用户授权，范围是 `quant/my_obr`。保留按订单模拟撮合、通过后续成交/撤单
推断市价行为的实验方案；`apply_market_order` 仍是同一个完整函数，没有拆分，其他
原有函数也保留原来的职责划分和名称。全部代码使用 C++11。

修改后，已知的无效访问和数值溢出会被检查拦住，并给出错误；正常情况下仍按原流程
生成实验盘口。这不代表市价类型推断已经得到交易所或数据源确认。

| 文件 | 修改内容 |
| --- | --- |
| [main.cpp](../src/main.cpp) | 参数、CSV、时间与输入范围检查；错误定位；最后事件边界；文件保护；精确价格输出 |
| [order_book.cpp](../src/order_book.cpp) | 空容器和引用检查；撤单量检查；五档停止；待撤量隔离；算术检查和回滚 |
| [model.hpp](../include/model.hpp) | 增加诊断/证券字段，以及源记录剩余量、待撤余量 |
| [order_book.hpp](../include/order_book.hpp) | 订单键改为频道与原订单 ASN 的组合，说明错误及状态契约 |
| [checked_math.hpp](../include/checked_math.hpp) | 两个 C++11 非负整数检查函数，复用于数量与金额运算；没有拆出撮合业务 |

具体修改如下。

1. **修复最后一个事件越界。**
   原来每轮都读 `events[index + 1]`。现在先判断是否已经是最后一条，只有确实存在下一条
   才读它。空输入、单条事件、文件最后一条都可以正常处理。

2. **所有需要的盘口或历史先检查存在性。**
   市价单读取对手最优档、仅撤销历史分支读取本方最优档、U 单读取本方最优档之前，都检查
   对应容器是否为空。最优档不足、实验分类需要历史却没有历史时，明确报错。
   历史索引使用 `find()` 和 `const vector&`，不再隐式插入空 vector，也不整份复制历史；
   `back()` 只在已确认非空后使用。

3. **修复市价卖单删除错误一侧。**
   当市价卖单恰好吃完买一时，现在删除 `bids` 中那个买档。原来的 `asks.erase(...)`
   会留下零数量买档，并可能误删同价卖档。

4. **五档分支处理完成后立即返回。**
   仍保留“最后一条关联记录是撤销就归为五档”的实验判断，但执行该分支时最多消费五档，
   不再落入后面的扫盘循环。六档各 10、来单 60 的验证中，第六档保留 10。

5. **待撤余额不再使用 `-1` 价格入簿。**
   新增 `OrderInfo::pending_cancel_quantity`：五档分支尚未成交的余额放在订单登记里，
   不写入 bids/asks；后续真实撤单只减少待撤量，不碰真实价格档。
   原“跨价扫盘”分支扫完后仍有余量，也记录在此字段，避免数量无记录地消失。
   这是对既有未入簿余量的记账，并没有新增一种确定的交易所申报类型。
   后续订单和快照不会再把该余额当成负价格挂单。

6. **余量合并使用累加，避免覆盖整档。**
   `TradeAtBest` 分支的余量若挂到已有同侧价位，现在进行检查后的累加，保留原档数量。
   该条件性问题通过有同价既存量的独立核心场景验证。

7. **撤单先定位原订单，再检查数量和价格档。**
   不再用 `order_price[id]` 把未知单变成默认记录。检查引用是否恰好一侧非零、与订单ID和
   原方向是否一致，检查原单剩余量以及目标档总量，全部通过后才扣减。
   未知订单、重复全撤、超量撤单、已经不存在的价位都会报错，失败不会留下部分扣量。
   完成的登记保留零剩余量，用于识别重复新单和已结束订单，未引入 FIFO 队列。

8. **区分“源记录剩余量”和“模拟价格档数量”。**
   新增 `OrderInfo::remaining_quantity`，初值是原委托量，按输入中已经出现的 F/4 减少。
   F 在 `apply()` 内检查双方订单、方向及可扣量，然后只更新两个订单登记。
   F 不会再次扣 bids/asks，也不会再次累计成交量/成交额，因此不把模拟撮合重复计算。
   F 也不能侵占已经被实验分支记为待撤的余额。

   例如同价 A、B 各 10，真实 F 引用 A 成交 4 后，撤 A 7 会失败；撤 A 6 后，B 的 10
   仍保留。这个检查依赖源 F/4 完整、引用正确；源记录剩余量与模拟盘口可能因实验推断
   不一致而发生冲突，此时报告错误，不把它解释成整套逐单重建已经准确。

9. **订单引用加入频道作用域。**
   两张索引表都使用 `(ChannelNo, 原订单 ApplSeqNum)`。同频道引用能够一致定位，不同
   频道相同 ASN 不会覆盖。主程序仍限制一次输入只有一个 SecurityID/secid 和频道，
   避免同一个实验盘口混入多个证券；一个 OrderBook 仍限定单证券、单交易日。
   本轮没有增加供应商未确认的交易日解析，也没有实现多证券分发。

10. **在执行运算之前检查 int64 范围。**
    价格档累加、竞价买卖量求和使用 `checked_add`；价格乘数量使用 `checked_multiply`；
    成交累计量和金额先全部算出合法新值，再一起赋值。
    输入和核心均拒绝不合法的零/负数量、负价格及零限价。撮合扣量使用不超过现有量的
    `min`；撤量先比较范围，避免负档位传播。
    竞价差额用较大值减较小值，消除了有符号相减及 `abs(INT64_MIN)` 风险。
    超范围报 `std::overflow_error`，不继续使用回绕后的数。

11. **新订单处理失败会回滚。**
    `apply()` 处理新单前复制两侧价格档并保存统计、快照标志。发生错误时用 `swap`
    恢复盘口，恢复统计和标志，删除本次插入的登记，再把异常交给 main。
    不复制全日成交历史或全部订单登记。撤单、源 F 采用“全部检查后再更新”；
    建历史索引时第二侧写入失败也会撤回第一侧的新增内容。

    代价是每个新订单额外执行 O(L) 的盘口复制，L 为当时有效价格档总数，并产生 O(L)
    临时内存。这是本轮为了保持函数结构而选择的直接实现；还没有进行真实规模性能验证。
    后续可以讨论事务日志，但本轮没有引入它。

12. **集合竞价处理空状态和收尾。**
    空盘口、单边盘口或无成交量时不读取空候选，不记录零量成交。
    候选检查补上“更优买卖申报可以全部成交”的约束；保留现有最大量/最小差额筛选框架。
    如果多个最优候选仍无法区分，明确报需要参考价格，不随意挑一个。
    累计量/金额检查放在两侧扣档之前，使结算失败不改变原盘口。
    main 在开盘、收盘集合竞价阶段结束或 EOF 时都调用收尾。实验 writer 仍只输出
    连续阶段快照，因此收盘结算成功不意味着会多出收盘 CSV 行。

13. **CSV 和命令行失败变成可定位的错误。**
    四种选项缺值、未知/重复选项、缺必需输入都会报错，提供 `--help`。
    原始两表表头按约定逐字检查，包括 `exchld`、`__isRepeadted`、`TradyMoney`。
    检查 20/22 列、有效 Side/OrderType/ExecType、引用及数量。数字必须被完整解析，
    `123abc`、小数价格、超范围整数不再被截取前缀接受。支持 CRLF，暂明确拒绝带引号 CSV。
    文件读取/关闭失败均检查，行错误包含文件名和行号；重放错误增加 caa、sequenceNo、order_id。
    main 捕获标准异常后打印 `my_obr: ...` 并返回非零状态。

14. **限定排序与时间的当前实验契约。**
    保持按 sequenceNo 排序，但相等序号拒绝处理，不让重复事件或不明确次序重复变更状态。
    检查阶段在排序后是否倒退。没有把序号必须连续、不同序号字段间的关系等未确认规则写死。
    TransactTime 沿用原 HHMMSSmmm（可省略前导0）假设，补上格式和合法时分秒检查；
    仍保留原秒级端点，午休、盘前、明显盘后等不再统一归入收盘集合竞价。
    caa 只要求非空并原样保留，不擅自新增必须为整数时间戳的要求。

15. **修复输出路径、流错误与价格精度。**
    只有指定 `--events-output` 才导出 events；打开、写入和关闭失败都报错。
    拒绝输入与输出或两份输出指向同一文件，检查普通路径、软链接和硬链接；对无法解析
    目标的悬空输出软链接直接拒绝，避免先创建 events 后又被 book 覆盖。
    该路径检查使用 POSIX `stat/lstat/realpath`，适用于当前 macOS/Linux 环境，未验证 Windows。
    价格输出改成整数除余数，精确保留四位小数，例如 `123456` 输出 `12.3456`，不再变成
    `12.35`；同时避免 INT64_MIN 取负溢出。价格输入仍要求是已放大 10000 倍的整数，
    这是原代码的实验假设，不是依据表头新确认的供应商定义。

16. **保留用户修改，清理剩余调试输出。**
    你删除的两段调试代码保持删除；另清理了残留的固定 caa 打印和旧快照调试注释。
    没有为了消除编译告警关闭生产告警；两个未使用的迭代器已删除。

下面这些实验行为按本轮范围保留，便于你下一次自己调整：

- 最优档量足够时直接模拟成交；只有一条撤销历史时仍尝试按本方最优价挂量。
- 末条撤销推断五档、不同成交价推断跨价、同价推断对手最优余量等分类条件。
- 真实 F 用于登记校验，实际盘口和成交统计仍主要由订单模拟撮合产生。
- 各市价分支原来的 `generate_snapshot` 决策，及 writer 只输出连续阶段的策略。
- book 仍是既有 21 列实验格式，包括 `bp4`；没有扩成总体规划中的 30 列，也没有新增
  真实成交笔数、开盘价、最后成交价等功能。完整格式中的 `bo4` 是另一项明确契约。
- 集合竞价完整的参考价格、价格范围和历史数据适用规则还需继续核对；本轮不宣称已完成
  交易所级重建，也不将合成数据通过视为真实行情已覆盖。

特别注意现在会明确停止的情况：所需盘口为空、必要历史缺失、真实引用或剩余量与实验
结果冲突、竞价价格无法唯一确定、输入超出单证券/频道范围，以及数值或文件错误。
例如会显示 `market order has no opposite level; empty-book policy is unresolved`。
这里修复的是原来的无效访问，并没有悄悄选定“自动忽略”或“自动撤销”的新业务策略。
程序返回非零时，本次重放结果不能当作成功结果；可选 events 导出发生在重放前，可能已经
存在。最终 book 只在重放成功后写入，但文件写入失败仍可能留下部分输出文件。

在工作区根目录可以用如下命令构建（输出目录可自行指定，避免覆盖输入文件）：

```bash
clang++ -std=c++11 -pedantic-errors -Wall -Wextra -Wconversion \
  -Wsign-conversion -Wshadow -Werror -O2 \
  -I quant/my_obr/include \
  quant/my_obr/src/main.cpp quant/my_obr/src/order_book.cpp \
  -o /tmp/my_obr_fixed

/tmp/my_obr_fixed --help
/tmp/my_obr_fixed --order /path/to/order.csv --trade /path/to/trade.csv \
  --output /path/to/book.csv --events-output /path/to/events.csv
```

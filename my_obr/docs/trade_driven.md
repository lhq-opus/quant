# my_obr：由真实 trade 驱动成交

现在不再由订单模拟撮合。程序仍只读取原始 `order.csv`、`trade.csv`，按 `sequenceNo`
排序重放；不读取目标 book，也不使用 `TradeBSFlag`、`OrderIndex` 推测成交关系。
本次直接修改现有版本，保留 C++11、整数价格、中文注释和 `PriceLevels` 封装。

## 三种事件各做什么

- `order`：保存原订单引用、方向、挂价和完整 `OrderQty`，按挂价增加本方价格档。
  即使买价高于卖价，也不自动撮合、不产生任何成交统计。
- `ExecType=F`：用 `ChannelNo + BidApplSeqNum/OfferApplSeqNum` 找到双方原单，
  两张订单各扣一次 `TradeQty`；已挂档的订单再从各自挂价扣同样的量。
  笔数、成交量和金额只累计一笔。
- `ExecType=4`：按唯一非零引用找到原订单，扣 `TradeQty`；已挂档时同步扣对应价格档。
  撤单不计成交笔数、成交量和成交额。

例如买单挂价11元、卖单挂价10元，某条F成交3股：应从买侧11元档和卖侧10元档
各扣3股，不能把两边都定位到 `TradePrice` 价档。在F扣量步骤中，成交价用于统计，
不用于定位原订单的挂价。
同价有多张单时，也先按引用减少指定订单的余量，不能拿整档总量代替某张订单的余量。

核心关系是：

```text
订单剩余量 = 原OrderQty - 已处理的关联F数量 - 已处理的关联4数量
价格档数量 = 本侧、本挂价下所有已挂档订单的剩余量之和
```

## 限价、本方最优和市价

限价 `2` 用原始 `Price` 挂完整数量；`U` 在到达时取一次本方最优价并保存，后续
本方最优价变化不会改变这张单已经保存的挂价。

市价 `1` 的挂价仍沿用之前获准保留的实验推断。预读关联F/4只用来决定是否挂档及
挂价，不执行未来事件、不提前扣未来数量，也不根据非零原始 `Price` 自动改成限价单：

- 当时对手最优档足够容纳该单：不挂本方档，登记完整数量等待F/4。
- 对手最优档不足，且历史只有一条撤单：沿用暂挂本方最优价的实验规则。
- 对手最优档不足，多条关联记录以撤单结束，或关联成交有不同于当时对手最优价的价格：
  不挂本方档，但保留完整订单余量。
- 对手最优档不足，其余关联成交都在当时对手最优价：以该价挂完整量，后续F扣掉
  已成交部分，余量自然留下。

最后两类判断继续按原先的优先顺序执行，具体见 `find_market_order_price()`。
**这些是项目实验假设，不是已经确认的市价子类型规则。** 如果实验不挂档，但某张
真实市价单的余量实际上应挂档，五档结果仍可能缺量；改成F驱动不会自动解决挂价歧义。
空盘口或缺少推断所需历史时保留原有明确报错，不新增默认价格或恢复策略。

不挂档的订单使用 `OrderInfo::price=0` 表示，F/4仍然扣它的登记余量，只跳过价格档
扣量。不存在“模拟待撤量”了，也不再自行限制最多成交五档；真实F引用第六档，就
处理第六档，后续4撤多少就扣多少。

## 集合竞价

开盘和收盘也使用同一个 `apply_trade()`：到达的订单先登记，真实F到达再扣双方。
不再运行 `find_call_action_result()`、`finish_call_auction()`，不从候选价格计算
虚拟成交，也不在时段末再扣一遍。

因此，输入必须包含所需的真实竞价F。缺失成交时，程序不会靠撮合猜出或补齐结果。
开盘价取全日首条F的 `TradePrice`，最新价随F更新；这是重建当天实际成交，不是
计算尚未发生的竞价理论结果。仍只导出连续交易阶段的快照，竞价状态和统计带入后续。

## CAA快照区间

每个连续阶段的订单或撤单都作为快照起点，包括市价单；F只改变状态，不单独生成行。
实际保存快照的时机是：处理完该起点及其后、下一条order/4之前的全部F。
顺序用 `sequenceNo`，不是用CAA比较大小；CAA即使相同，也不合并不同起点。

例如 `卖单A → 买单B → F成交4 → F成交6 → 新单C`：

- A的快照保存于B入簿之前；
- B先登记，不撮合；两条F分别扣4、扣6；
- C入簿之前保存B的快照，它已含两笔成交后的盘口及统计，但元数据仍取B；
- 若文件以这两条F结束，也会补存B的最终快照。

时段变化会先结束前一阶段的待输出快照，不将收盘F计入最后一张连续交易快照。
30列表头、`bo4`拼写、整数数量和四位小数规则不变，详见[输出说明](book_30_columns.md)。

## 阅读和验证

建议依次看 `add_order()`、`apply_trade()`、`apply_cancel()`，最后看 `main()` 的
待输出快照循环。价格档的读写仍只通过 [PriceLevels](price_levels.md)。

原有引用、余量和整数范围校验保留。F在扣量前检查双方和全部统计运算，通过后才
一起更新；单档加量失败仅移除新订单登记，不再每张新单复制整个盘口。

本轮临时合成数据覆盖46组合法输入及12组失败输入，在Debug、Release、ASan/UBSan
三种C++11构建下通过；每版2096行快照独立逐字段核对30列，包含20个固定随机种子。
所有12列events导出与改动前一致。核心另有328项断言覆盖原单引用、挂档/不挂档余量、
竞价F和失败原子性，三种构建均通过。验证程序和CSV不提交，未使用用户真实行情。

编译命令不变，仍需要三个cpp：

```bash
clang++ -std=c++11 -pedantic-errors -Wall -Wextra -Wconversion \
  -Wsign-conversion -Wshadow -Werror -O2 \
  -I quant/my_obr/include \
  quant/my_obr/src/main.cpp quant/my_obr/src/order_book.cpp \
  quant/my_obr/src/price_levels.cpp -o /tmp/my_obr

/tmp/my_obr --order /path/to/order.csv --trade /path/to/trade.csv \
  --output /path/to/book.csv --events-output /path/to/events.csv
```
